# SOP Guide

This directory contains standard operating procedures for repeatable work.

An SOP should describe a small, reusable action pattern. It should be clear enough for a human or AI agent to follow without guessing the intended order of work.

## What Belongs Here

Add an SOP when:

- The same task pattern appears more than once.
- The order of steps affects quality or safety.
- A task benefits from explicit inputs, outputs, and verification.
- The procedure is reusable across projects created from this template.

Do not add an SOP for one-off project knowledge, broad principles, or temporary notes.

## Naming

- Use lowercase kebab case.
- Use a noun phrase or verb phrase.
- Keep names short and specific.

Examples:

- `task-intake.md`
- `release-check.md`
- `bug-triage.md`

## Recommended Structure

Each SOP should use this structure unless there is a good reason to differ:

```md
# SOP Name

## Purpose

## When To Use

## Inputs

## Steps

## Output

## Verification
```

## Maintenance Rules

- Keep SOPs operational, not philosophical.
- Prefer checklists and decision points over long prose.
- Update an SOP when repeated use reveals a gap.
- Split an SOP only when it starts covering multiple independent procedures.
